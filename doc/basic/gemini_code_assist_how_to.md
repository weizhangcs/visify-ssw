# Gemini Code Assist 实战指南 (How-To)

本文档总结了在本项目中使用 Gemini Code Assist 的核心逻辑、最佳实践与提示词技巧。

## 1. 核心交互模式：Ask vs Agent

理解这两种模式的区别，有助于在不同场景下选择正确的交互方式。

| 模式 | 角色定位 | 典型场景 | 交互逻辑 |
| :--- | :--- | :--- | :--- |
| **Ask (Chat)** | **咨询顾问** (Read-Only) | 技术问答、解释代码、生成局部函数、编写正则/SQL | **你问我答**。AI 提供思路或代码块，需人工复制粘贴。 |
| **Agent** | **数字员工** (Read-Write) | 跨文件重构、批量修改、根据业务逻辑完善代码 | **你吩咐，我干活**。AI 直接生成 Diff，需人工 Review 并接受。 |

## 2. 上下文卫生 (Context Hygiene) —— 避免幻觉的关键

IDE 插件版的 AI 极其依赖**本地上下文**。为了防止 AI 编造不存在的变量或方法，请遵循以下原则：

### A. "Open Tabs" 策略 (最重要)
**你打开的文件 = AI 的短期记忆。**
*   **场景**：修改 `context.py` 以适配 `probe.py` 的接口。
*   **操作**：务必同时在编辑器中打开这两个文件。
*   **效果**：AI 能直接看到函数签名，从而生成准确的参数调用，消除幻觉。

### B. 显式锚定 (Explicit Anchoring)
*   **选中代码**：在提问前，选中你关注的函数或类。这会强制 AI 聚焦于选中的 Token。
*   **引用文件**：在 Prompt 中明确提及文件名（如 `@probe.py`），告知 AI 搜索范围。

## 3. 提示词工程 (Prompt Engineering)

在 IDE 场景下，使用 **RCAC 公式** 来构建高质量指令：

> **Role (角色) + Context (上下文) + Action (动作) + Constraints (约束)**

### ✅ 优秀 Prompt 示例

**场景：重构代码**
> **(Role)** 作为 Python 后端专家，
> **(Context)** 参考 `apps/refinery/services/probe.py` 中 `ProbeService.run` 的返回值签名，
> **(Action)** 修改 `apps/atomflow/refinery/context.py` 中的 `_handle_probe` 方法，
> **(Constraints)** 确保正确解包元组，并处理可能出现的 `IndexError`，不要引入新的第三方库。

### 💡 高级技巧

1.  **思维链 (Chain of Thought)**:
    *   对于复杂逻辑，在 Prompt 结尾加上：“**Let's think step by step. Explain your plan first, then show the code diff.**”
    *   这能大幅减少逻辑漏洞。

2.  **负向约束 (Negative Constraints)**:
    *   明确告诉 AI **不要做什么**。
    *   例如：“保持使用 `subprocess`，不要将其重构为 `os.system`。”

3.  **提供样本 (Few-Shot)**:
    *   如果你需要特定的日志格式或代码风格，给它一个现有的例子作为参考。

## 4. 领域知识注入 (Docs as Code)

如何让 AI 理解项目的架构设计和业务规则？

1.  **格式转换**：将 Word/PDF 架构文档转换为项目中的 Markdown 文件（如 `doc/architecture.md`）。
2.  **级联上下文**：
    *   在进行复杂业务开发时，**打开**相关的 Markdown 文档。
    *   AI 会读取文档内容作为背景知识，从而生成符合架构规范的代码。

### 推荐文档结构
*   `doc/architecture.md`: 系统分层、设计模式约定。
*   `doc/business_rules.md`: 核心业务逻辑定义。
*   `doc/db_schema.md`: 关键数据模型关系。
